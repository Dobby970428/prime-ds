# PRIME-DS 배포본 만들기

2026-10-07 · Python 이 없는 PC 에서도 돌아가는 포터블 배포본을 만드는 키트입니다.

---

## 한 줄 요약

`배포_빌드.bat` 더블클릭 → 10~20분 → `_dist\PRIME-DS_포터블.zip` 완성.
받는 사람은 압축 풀고 **`PRIME-DS 실행.bat`** 더블클릭. 그게 전부입니다.

---

## 1. 왜 이 방식인가

| 방식 | 판단 |
|---|---|
| **Python embeddable 런타임 동봉** ← 채택 | python.org 가 배포하는 «설치가 필요 없는 Python» 을 배포본 폴더 안에 넣고, 거기에 패키지를 설치합니다. 레지스트리·PATH·시스템 Python 을 일절 건드리지 않습니다. |
| PyInstaller 로 exe 하나 | RDKit 은 C++ 확장과 데이터 파일(주기율표·SMARTS 사전 등)을 런타임에 찾아 읽습니다. scikit-learn 도 숨은 import 가 많습니다. 번들에 빠져도 **조용히** 빠지고, 엉뚱한 시점에 터집니다. 논문에 실린 수치를 재현해야 하는 도구에는 맞지 않습니다. |
| Docker | 받는 쪽에 Docker 를 깔아야 합니다. Python 설치보다 무겁습니다. |

포터블 폴더는 USB 로 옮겨도 되고, 지울 때 폴더만 삭제하면 흔적이 남지 않습니다.

## 2. 빌드하는 쪽 (성준님 PC, 한 번)

### 필요한 것

- Windows 10 64비트 이상
- **인터넷** — 이 빌드 때만 씁니다 (Python 런타임과 패키지를 내려받습니다)
- 여유 공간 약 3 GB
- Python 설치는 **필요 없습니다**

### 순서

```
배포\배포_빌드.bat          ← 더블클릭  (10 ~ 20분)
배포\검색데이터_추가팩_빌드.bat  ← 검색 데이터가 필요할 때만 (10 ~ 30분)
```

### 키트 7개 파일은 반드시 한 폴더에

`배포_빌드.bat` 하나만 복사해 두면 동작하지 않습니다. 아래 7개가 **같은 폴더에**
있어야 합니다. 프로젝트의 `배포\` 폴더에 전부 들어 있습니다.

```
배포_빌드.bat  ·  검색데이터_추가팩_빌드.bat  ·  _build.py
_verify.py  ·  _build_searchpack.py  ·  requirements-dist.txt  ·  README_배포.md
```

빠진 파일이 있으면 **다운로드를 시작하기 전에** 어떤 파일이 없는지 알려 주고 멈춥니다.

### 키트를 프로젝트 밖에 두고 싶을 때

프로젝트 폴더는 `p00_flask_app.py` 가 있는 곳으로 자동 판별합니다. 찾는 순서는
① 명령줄 인자 → ② 키트 폴더의 부모 → ③ 키트 폴더 자신. 전부 아니면 이렇게
경로를 주면 됩니다.

```
배포_빌드.bat "<프로젝트 폴더 경로>"
```

탐색기에서 프로젝트 폴더를 `배포_빌드.bat` 위로 **끌어다 놓아도** 같습니다.

결과물은 프로젝트 폴더 아래 `_dist\` 에 생깁니다.

```
_dist\
  PRIME-DS\                      ← 폴더 그대로 복사해도 동작
    PRIME-DS 실행.bat
    자가점검.bat
    README.txt
    runtime\                     Python 3.12 + 패키지
    app\                         엔진·웹앱·모델·실측 DB
  PRIME-DS_포터블.zip             ← 배포용
  PRIME-DS_검색데이터팩.zip        ← 선택
```

### 빌드가 하는 일

1. python.org 에서 **Python 3.12 embeddable** 을 받습니다 (최신 패치부터 차례로 시도)
2. `python312._pth` 를 고쳐 `Lib\site-packages` 와 `..\app` 을 경로에 넣습니다
3. `get-pip.py` 로 pip 를 심고 `requirements-dist.txt` 대로 패키지를 설치합니다
4. 배포본에 들어갈 파일만 골라 `app\` 으로 복사합니다
5. **복사된 배포본을 실제로 기동해 7가지를 검사합니다** (아래 4절)
6. 검사를 전부 통과하면 ZIP 으로 묶습니다

5번을 통과하지 못하면 ZIP 을 만들지 않고 멈춥니다. 망가진 배포본이 나가지 않도록 한 것입니다.

## 3. 받는 쪽

1. `PRIME-DS_포터블.zip` 압축 해제
2. `PRIME-DS 실행.bat` 더블클릭
3. 브라우저가 `http://127.0.0.1:8501/` 로 자동으로 열립니다

Python·pip·인터넷 전부 필요 없습니다. (PubChem 조회 기능만 인터넷을 씁니다.)

검색 모듈까지 쓰려면 `PRIME-DS_검색데이터팩.zip` 을 **같은 폴더에** 풀고
`검색데이터_재색인.bat` 을 한 번 실행하면 됩니다.

## 4. 자가점검이 보는 것 — `app\_self_check.py`

배포본이 «켜지는지» 가 아니라 «논문과 같은 답을 내는지» 까지 봅니다.
다른 PC 로 옮긴 뒤 `자가점검.bat` 을 돌려도 같은 검사를 다시 할 수 있습니다.

| # | 검사 | 통과 기준 |
|---|---|---|
| 1 | 필수 패키지 | 11개 전부 import · 버전 출력 |
| 2 | 모델 ↔ scikit-learn 버전 | 피클에 기록된 버전과 설치된 버전이 **일치** |
| 3 | Layer C | 모델 적재 · 엔드포인트가 Ames 인지 · NDMA 와 아세트산 예측 |
| 4 | Layer A | `cache\m7_empirical.db` 열고 행 수 (5,324행) |
| 5 | 구조 경보 | NDMA 가 N-nitroso 경보에 걸리고, 아세트산은 안 걸리는지 |
| 6 | 웹 화면 | 등록된 GET 화면 14개가 전부 500 을 내지 않는지 |
| 7 | 보고서 출력 | docx · pdf · xlsx 생성 |

리눅스 컨테이너에서 같은 검사를 미리 돌려 7건 전부 통과하는 것을 확인했습니다.
(NDMA P=0.920 · 아세트산 P=0.010 · m7_empirical 5,324행 · 경보 21종 · 화면 14개)

## 5. 버전을 고정한 두 가지 — 중요

`배포\requirements-dist.txt`

### `scikit-learn==1.9.0`

`models\ames_ecfp_rf.pkl` 안에 `_sklearn_version = '1.9.0'` 이 박혀 있습니다.
다른 버전으로 열면 경고 한 줄만 내고 넘어가거나(**조용한 오작동**), 내부
자료구조가 바뀐 경우 적재에 실패합니다. Layer C 는 앙상블 판정의 한 축이므로
여기서 어긋나면 판정 결과가 통째로 달라집니다.

모델을 다시 학습하지 않는 한 이 줄은 바꾸지 마십시오. 자가점검 2번이 바로
이 어긋남을 잡기 위한 검사입니다.

### `rdkit==2026.3.6`

원고 §2 가 명시한 버전이고, `cache\ad_train_fps.pkl` 과
`cache\substruct_primary.pkl` 이 이 버전으로 만든 지문 피클입니다.

나머지는 상한만 걸었습니다 — `pandas<3.0`(3.0 은 동작이 바뀐 메이저 릴리스),
`numpy<3`, `fpdf2<3`(이미 deprecated 된 API 를 쓰는 곳이 두 군데 있습니다).

## 7. 막혔을 때

| 증상 | 손볼 곳 |
|---|---|
| `requirements-dist.txt` 없음 | 키트 7개 파일이 한 폴더에 있지 않습니다 (2절) |
| 프로젝트 폴더를 못 찾음 | 프로젝트 경로를 인자로 주거나 폴더를 bat 위로 끌어다 놓으세요 (2절) |
| 런타임을 못 받음 | 사내 프록시. `배포_빌드.bat` 이 시도한 URL 을 브라우저로 직접 받아 `<프로젝트>\_dist\_work\python-embed.zip` 로 저장한 뒤 다시 실행하면 그 파일을 씁니다. `get-pip.py` 도 같은 식으로 미리 받아 두면 재사용합니다 |
| 패키지 설치 실패 | `set HTTPS_PROXY=http://주소:포트` 후 재실행 |
| 자가점검 2번 실패 | 모델을 만든 scikit-learn 버전이 바뀐 것입니다. 메시지에 나온 버전으로 `requirements-dist.txt` 를 맞추세요 |
| 자가점검 6번 실패 | `_build.py` 의 복사 목록에서 빠진 모듈이 있습니다. 메시지의 화면 경로를 보고 추가하세요 |
| 실행은 되는데 Search 가 비어 있음 | 정상입니다. 검색 데이터 추가팩을 풀어 주세요 |
| 8501 포트 충돌 | `set PRIME_FLASK_PORT=8600` 후 실행 |

## 8. 아직 결정되지 않은 것

논문 배포용 공개 저장소에 이 배포본을 함께 올릴지는 원고를 마친 뒤 정하기로
했습니다. 올리게 되면 그때 확인할 것:

- `toxtree_sources\` 에서 옮겨 적은 SMARTS 의 라이선스 표기 (A·B·C 안 중 선택)
- `data\CID*.csv` 의 출처 표기 (PubChem 이용 조건)
- Layer C 모델·실측 DB 를 함께 배포할지, 저장소에서 내려받게 할지
